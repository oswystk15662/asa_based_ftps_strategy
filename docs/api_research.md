# AsaApi 技術調査

確認日 2026-11-24 JST。対象は Windows x64 の ASA 専用サーバー。公式と記す AsaApi 資料はメンテナーの一次資料。Studio Wildcard がサポートするゲーム SDK とは別系統。

## 版・導入・運用

- 公開名 **ASA: Server API**、プロジェクト名 **AsaApi**。2024-03-18 以降の保守主体は ArkServerApi。最新安定版は 2.11（GitHub 公開 2026-11-08 UTC、タグ SHA `bd376a0422291b0b1bf15a0b7868e7e275605da9`）。既定ブランチ先端は確認時 `d58e6daf8992ee30ea45f2e9b2aa856a8bde5f63`。ライセンスは MIT、同梱依存は個別確認。ASE の AseApi は別リポジトリ。 [README](https://github.com/ArkServerApi/AsaApi/blob/2.11/README.md) [2.11](https://github.com/ArkServerApi/AsaApi/releases/tag/2.11) [LICENSE](https://github.com/ArkServerApi/AsaApi/blob/2.11/LICENSE)
- Wildcard が公表した比較基準は公式サーバー v98.9（11/18。Steam クライアントも v98.9、他クライアントの v98.11 は別）。取得する Steam 専用サーバーの実行版・buildid は未確認。2.11 の告知に v98.9 対応保証や完全な対応表を確認できず、対象ビルドとの互換性は PoC 01/02 で判定。2.11 の欠落オフセット隔離は次回起動時の処置であり、初回停止に備える。 [Wildcard サーバー告知](https://survivetheark.com/index.php?/forums/topic/773786-asa-server-patch-notes-server-v989-updated-11182026/) [クライアント告知](https://survivetheark.com/index.php?%2Fforums%2Ftopic%2F708761-asa-pc-patch-notes-client-v989-updated-11192026%2F=&comment=3625322&do=findComment) [2.11 変更点](https://www.ark-server-api.com/resources/asa-server-api.31/updates#resource-update-1307)
- 配布物とローダーをテストサーバーの `ShooterGame/Binaries/Win64` に配備する。別配布の VersionLoader v1.0 を使う場合は `version.dll` とともに `ArkAscendedServer.exe` を起動。実行型 `AsaApiLoader.exe` を選ぶ場合は同時にその `version.dll` を配置しない。ネイティブ Linux サーバープラグインは確認できず、Wine での互換性は初期対象外。Linux クロスビルドの案内は Windows 用 DLL のビルド手段。 [ローダー v1.0](https://github.com/ArkServerApi/AsaApiLoader/releases/tag/v1.0) [Windows のビルド定義](https://github.com/ArkServerApi/AsaApi/blob/2.11/AsaApi/AsaApi.vcxproj#L8-L29)
- Plugin は Windows x64 DLL。2.11 のヘッダーと同版 `AsaApi.lib` をリンクし、`Plugin_Init` / `Plugin_Unload` をエクスポート。タグの本体 vcxproj は v145/C++20 を指定し、README の 14.39 記述は一致しない。公開テンプレートの既定は 1.19 用。初回は配布 lib と既設 v143 で小さい DLL のコンパイル・リンク・ロードを試し、失敗時は診断に基づき v145 等の追加導入を承認事項にする。v143 での互換性は未確認。 [vcxproj](https://github.com/ArkServerApi/AsaApi/blob/2.11/AsaApi/AsaApi.vcxproj#L14-L60) [テンプレートのビルド手順](https://github.com/MolluskARK/ASA-Plugin-Template#1-obtain-asaapilib)
- `Win64/ArkApi/Plugins/<名前>/` に同名 DLL と `PluginInfo.json` を置く。起動時にスキャンし、登録済みの `plugins.load <名前>` / `plugins.unload <名前>` は管理コンソールと RCON の両経路にある。開発の基準は停止・置換・再起動。ホットアンロードは停止フラグ、コールバック/フック除去、ワーカー停止と完了待ちを確認したあとに使う。自動リロードは保存を伴うコード経路がある。 [コマンド登録](https://github.com/ArkServerApi/AsaApi/blob/2.11/AsaApi/Core/Private/Ark/ArkBaseApi.cpp#L785-L900) [ロード/解除](https://github.com/ArkServerApi/AsaApi/blob/2.11/AsaApi/Core/Private/PluginManager/PluginManager.cpp#L43-L295) [自動更新処理](https://github.com/ArkServerApi/AsaApi/blob/2.11/AsaApi/Core/Private/PluginManager/PluginManager.cpp#L381-L468)
- デバッグでは DLL と同ビルドの PDB を自前で保存し、Visual Studio ネイティブデバッガをテストの `ArkAscendedServer.exe` にアタッチする。Modules で DLL とシンボルを照合し、初期化・tick・解除を観測。AsaApi ログと Saved/Logs、Windows イベント、同版ビルド情報を突合。起動失敗はバニラ→ローダー→DLL の順で切り分ける。
- 更新前に隔離環境で再起動・状態読み出し・実体作成/保存のスモークテストを実施する。キャッシュやオフセット、フィールドサイズ、BP パス、シリアライズのいずれも版で壊れ得る。実行ファイル・ローダー・AsaApi・DLL・MOD・セーブの対応表を残し、復元は互換セットと対応するバックアップが揃う場合に行う。
- AsaApi 本体には実行ファイルに対応するオフセットキャッシュを外部 CDN から取得する経路がある。DLL とシミュレーターの通信はローカルに制限し、ローダー導入後の PoC 01 では本体の外向き通信・キャッシュ取得の結果を起動ログで確認する。 [キャッシュ初期化](https://github.com/ArkServerApi/AsaApi/blob/2.11/AsaApi/Core/Private/Ark/ArkBaseApi.cpp#L270-L325) [キャッシュ取得](https://github.com/ArkServerApi/AsaApi/blob/2.11/AsaApi/Core/Private/Ark/ArkBaseApi.cpp#L385-L430)
