# データモデルと状態管理

| 記録 | 主な属性と関係 | 状態の正 |
|---|---|---|
| World / Zone | world_id、マップ・座標基準、稼働 boot_id、境界、観測時刻・完全性 | 範囲と管理設定は外部、実体が存在する現況は ASA |
| Civilization / City | UUID、外交、技術、人口、建設・生産計画、所属、領域セル | 外部。対応 ASA トライブとゲーム内権限は ASA |
| Person / Cohort | 個体・集団 ID、所属、職業、人数または個体、健康、装備参照、Task | 遠隔状態は外部。実体化時の位置・HP・装備現物は ASA |
| Facility / GameBinding | 施設 ID、計画、座標、部材、実体キー、クラス、所有、revision、観測時刻 | 計画は外部。配置・耐久・所有・電力は ASA。対応索引は外部 |
| TerrainSample / RoadNode / RoadEdge | 固定座標、面法線、水域、信頼度、地図版。区間、費用、容量、対応施設、通行可能性 | 観測値と実体は ASA。グラフ・計画は外部 |
| Inventory / ResourceEntry / Shipment | 保管場所、資源・単位、ロット、予約、取引 ID、工程、数量と移送中在庫 | 外部備蓄は外部。実物在庫は ASA。移送中の責任はジャーナル |
| Task / Command / Event / Snapshot | ID、依存、期限、事前条件、バージョン、成功・失敗、カーソル、範囲 | Task は外部。ゲーム適用の事実は観測で確定 |

論理 ID は UUID、実体キーは world_id・型・ゲーム内 ID の組合せ。StructureID や DinoID を使う前に PoC 13 で再起動安定性・再利用を検証する。NPC に安定キーがなければ再起動またぎの自動変更対象から外す。ポインターや名称の一致だけで対応付けない。ゲームから未観測の物体は「存在不明」、確定した破壊イベントか完全な観測で照合できた消失だけを破壊と確定する。

## 予約・実行・復旧

1. シミュレーターは資材の予約、操作 ID、対象セル、事前条件、期待する観測結果を一つの SQLite トランザクションに記録してから配送する。実行承認は一操作ごと。
2. DLL は同セッションの同 ID・内容を再実行しない。ゲームスレッドで所有、区画と占有、期待リビジョンを再確認。既存ゲーム側の永続タグが検証済みなら使い、得られなければ識別可能な専用セルと保守的な照合を使う。
3. 実行後の結果と再観測で配置・数量を確認し、外部の予約を決済する。資源移送は送出予約→送出確認→移送中→受領確認とし、同一ロットを両者の利用可能在庫へ入れない。仮想と現物で同一資源を重複生産しない。
4. 実行前の拒否は予約解除。実行後に応答が消えた場合は状態を unknown として予約を保持。ゲーム内在庫が片側だけ動いた場合は部分適用として隔離し、観測から補償できると確認してから別操作 ID で補償する。決済後にゲーム側だけ旧セーブへ戻った場合は再照合で差異を凍結し、確定した差分を逆仕訳または再適用する。
5. 起動時は world_id と保存世代を照合し、変更を停止した状態で対象区画の完全性を確認。対応候補を確証・欠落・競合・未観測で記録し、候補が曖昧なら停止する。区画外やプレイヤー所有の対象は照合のみ。既存オブジェクトの勝手な上書きや一括再生成を避ける。

セーブ時刻と DB トランザクションに原子性はない。GameSave の観測世代、外部チェックポイント、操作ログを記録する。PoC の復元用にサーバーを停止して新規テストワールドと対応 DB をペアで複製し、実機の保存完了を確認できる経路を決める。バックアップへ戻す場合はこの対応を使う。

## 近距離への移行と台帳

状態遷移は論理→実体化待ち→実体→抽象化待ち→論理。移行中は対象操作を凍結する。論理側で実体化を予約してからゲームの存在と所有を確認して権限を切り替える。抽象化ではゲーム側の観測値をスナップショットし、実体の管理状況と論理側の再開を一回だけ確定する。残存・休眠が疑わしいときは対象を保留し、陽に確かめる。建築は遠くなっただけで削除しない。プレイヤーが管理対象を破壊した場合、物理状態を更新して道路や生産の依存タスクを解除し、再建は新規計画として扱う。

数量は資源ごとの整数最小単位、時刻は UTC と simulation tick、計画の距離や方位は変換を明示。各資源の期末総量は期首＋観測済み採集＋工程産出−工程投入−消費−損失±外部持込出。内部移送は総量を変えない。人口・資源・実体対応の不変条件を再生テストで検証する。
