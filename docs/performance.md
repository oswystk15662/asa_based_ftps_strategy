# 性能設計と測定

以下の周期は試験設定の初期案。実測して負荷・遊びやすさを見直す。Level 0 が最高詳細度。

| 詳細度 | 保持状態 | 更新周期案 | 遷移・復元 |
|---|---|---|---|
| Level 0 実体 | ゲーム ID、位置、速度、HP、現物装備、割当と進行 | ASA tick、外部観測は 250 ms バッチを起点 | プレイヤーと観測可能な区画、実体上限、許可の条件を満たす。滞在後に ID と台帳の照合・権限移行 |
| Level 1 個体 | 個体 ID、区画、健康、職業、装備、道上の進捗 | シム 1–5 秒 | 可視化予算不足や距離増で抽象化。直近観測を引き継ぎ、復帰時は有効地点を再検査 |
| Level 2 集団 | 道路区間、人数、技能/HP 分布、装備合計、進捗 | 10–30 秒 | 同職業・区画で集約。分割は固定シードで分布から生成し、合計保存 |
| Level 3 都市 | 人口区分、在庫、工程、施設、物流予約、損耗 | 1–5 分 | 都市の仕事と資源から集団を割当て。既存実体の対応・輸送中予約を保持 |
| Level 4 国家 | 都市ごとの集計、戦略物資、外交、技術、戦線 | 15–60 分 | 都市スナップショットと集計差分を保持。復元時に都市間へ分配し、同じ消費を再実行しない |

昇格と降格は異なる距離しきい値と最低滞在時間を用いて振動を抑える。無人でもサーバーに残るアクターや休眠アクターは区別し、地形の観測可否も独立に扱う。復元の前提は [データモデル](data_model.md)。

## PoC 14 の計測

バニラ、ローダー、読み取り DLL、変更ありを順に比較。固定マップ・同じ版・同じセーブの複製、同じカメラとルートで、ウォームアップ後 10 分を各条件 3 回。クライアントなしと同居を別測定し、ビルド、設定、OS、時刻、電源モード、ゲーム内位置を記録する。NPC と建物を独立に 0→1→少数→倍増させ、各段階の上限と停止条件を先に決める。重い領域負荷、セーブ、ネット切断、再照合を個別に測定。

| 指標 | 記録方法 |
|---|---|
| サーバーフレーム時間 | 単調時計でサーバー tick の間隔、可能なら処理時間を別記。p50/p95/p99 と最大。DLL tick 内の処理は別スパン |
| CPU・メモリ | プロセス CPU、1 コア飽和、Windows コミット、ワーキングセット、ページング、ゲームと外部側の変化 |
| 同時 NPC 数・建物数 | 管理対象、観測済み、休眠、論理のみを区別。対象区画とマップ全体の観測範囲を記録 |
| 外部計算 | 経済・経路・計画 tick の個別時間、キュー滞留、再生シナリオの実時間比 |
| 通信量・実行遅延 | 方向別 byte/s・requests/s、送信から結果まで p50/p95/p99。待機と実行を分離し同一プロセス時計で RTT |
| 保存・ロード | 保存開始/完了の観測と起動から Ready まで、照合完了まで |
| 同期誤差 | 差分数、unknown 件数、再照合時間。資源・実体の重複/誤削除は失敗 |

性能値はバニラと読み取りの基準分布を採取して設定する。許容フレーム間隔、許容 p95 の増加、メモリ余裕、最大再照合時間を記録し、それを満たす直前の安全側の個体数/件数を各マップの暫定値にする。低下時は生成とキュー投入を停止し、必要に応じて処理を次 tick へ繰り越す。クラッシュ、継続的なページング、二重決済・誤変更はその段階で負荷試験を終了する条件。
