# 要求仕様

## 最小実用プロトタイプ

新規の専用ワールド、一つの集落、一種類の既存倉庫または土台、一種類の資源から始める。集落は小さな格子内で、在庫・地表法線・衝突・占有を評価して一件の建設を決める。建設前に資材を予約し、確認できた配置のみ決済する。観測、建設候補、コマンドと結果、台帳、再照合結果をログから追えるようにする。

受け入れ条件は、操作対象が PoC 用区画に限定されること、有効セルで配置した部材を確認できること、禁止セルと資源不足を拒否すること、切断や二重送信・再起動後も二重建設・二重決済がないこと。ゲーム内配置経路が不成立の場合は、同じ計画・台帳・照合を仮想アダプターで検証する。この場合は「外部のみ」の受け入れ結果と記す。人間型 NPC は PoC 06/07/11 の成功時に管理対象を一体追加して往復移動を評価する。失敗時は論理上の職業集団で採集・建設を表現する。

## 最終機能

| 領域 | 要求 |
|---|---|
| 文明 | 複数文明が人口・資源・技術・領土・軍事力を保持。独立した意思決定で建設、成長、交易、同盟、敵対、戦争、衰退、消滅を表現 |
| 都市 | 住宅・農地・倉庫・採掘・製造・発電・商業・道路・橋梁・港湾・防壁・防衛を需要に応じて追加。初期は格子、拡張時に斜度、水、資源、物流、防衛、余地を評価 |
| 道路 | 都市、資源拠点、港湾、軍事拠点を結ぶ。距離、斜度、水域、障害、安全、容量、需要、既存路、建設・維持費、拡張余地を評価 |
| 経済 | 採集、一次加工、部品・製品、建設、消費、輸送、在庫をモデル化。明示的な採集源・レシピ・損失・取引を台帳に記録。既存レシピや設備を優先し、統計生産にも入力・上限を課す |
| NPC | 職業、所属、位置、健康、装備、タスク。採集者、農民、鉱夫、建設者、工員、輸送員、商人、兵士を上位計画から割り当てる |
| スケール | 数十都市、論理上の数千～数万人、数百～数千の建築物、都市間ネットワークを長期目標とする。実体の同時上限は実測から決める |

## 非機能要求と制約

- 自前のローカル Windows 専用サーバーを起点とし、外部シミュレーターは Windows/Linux で同じシナリオを再生できる。クラウド契約・一般公開は初期範囲外。
- 固定シード・入力順・モデル版・マップ/アセットの版を記録する。各版のゲーム側変更は独立ワールドで検証する。
- 既存セーブ・MOD は保護する。許可した実体だけを操作し、通信障害や版不一致時には新規変更を停止する。
- プラグインのフレーム時間、CPU、メモリ、遅延、セーブ時間、同期誤差を計測。予算と同時実体数の上限は [性能計画](performance.md) に従って決定する。
- DevKit の導入は当面保留。独自 NPC アセット、独自メッシュ、ランタイム地形編集は後続の別判断とする。
