# アルゴリズム設計

更新周期はシミュレーション時間の初期案。地形変化や破壊のイベントで該当計画を無効化する。N は地形セル数、V/E はグラフの頂点/辺数、K は需要地点数、P は候補配置数、T はタスク数、W は労働者数、R はレシピ数、M は資源種類数、F は計画したフロー量。計算量は前提を添えた初期方式の目安。

| 問題 | 入力 → 出力 | 状態 / 決定変数 | 目的 / 制約 | 周期 | 初期候補・計算量 → 拡張 |
|---|---|---|---|---|---|
| 都市立地選択 | 高さ・水・資源・既存道・脅威 → 順位付き候補 | セルの適性・探索済み / 選択セル | 資源到達・拡張余地・防衛を最大化。未観測、水域、占有域、急斜面を除く | 定住需要発生時 | 重み付きスコア、距離場がキャッシュ済みなら O(N)。距離場作成は各 Dijkstra の費用を加算 → 複数候補の整合を評価 |
| 道路経路探索 | コスト格子、始終点、既存路 → 折線と許容部材 | 探索済み・累積費用 / 次セル | 工事費・斜度・距離・危険を最小化、橋モードで水域と支持を制約 | 接続需要・遮断時 | A*、二分ヒープで最悪 O((V+E) log V)。Dijkstra で複数目的地の距離をキャッシュ → 部材方向と橋状態をノードに加える |
| 道路ネットワーク設計 | 都市間需要、候補経路、容量 → 選択区間と建設順 | 既設辺・費用・需要 / 区間採択と容量 | 工事・維持＋需要加重輸送費を抑え、接続・予算・容量を満たす | 拠点追加・日次 | 候補距離計算 K 回の Dijkstra＋MST O(K² log K) の疎通骨格。需要上位の迂回改善を追加 → Steiner 近似と容量付きネットワーク設計 |
| 建物配置 | 建物 footprint・地形・支持・道 → 姿勢付き配置 | 占有格子・予約 / セルと向き | 道との距離・増設余地・地盤を評価。衝突、支持、所有、資材を制約 | 建設要求・失敗時 | 候補列挙 O(P·b)、b は footprint セル数 → 制約充足探索と複数棟の調整 |
| 土地利用計画 | 建物需要・危険・輸送・水 → 用途別区画 | 現在用途・密度 / セル用途 | 産業のアクセス・住宅環境・将来の増設。排他・最低面積・防壁区画 | 日次・都市拡張時 | 用途数 Z に対して O(NZ) の適性採点と貪欲割当て → 地区レベルの整数計画 |
| 資源配分 | 在庫・予約・要求・優先度 → 割当数量 | 資源台帳・不足量 / 優先需要への割当て | 食料と必需品欠乏、待ち時間を低減。在庫非負、予約を尊重 | 経済 tick・需要更新 | 資源別要求 T 件を優先度順に O(MT log T) 上界 → 希少資源に線形計画 |
| 生産計画 | レシピ・設備・労働・在庫 → 工程と開始量 | 残工程、原材料、設備キュー / 生産バッチ数 | 需要充足・余剰抑制。材料、技術、労働、電力、処理能力上限 | 経済 tick、設備変化時 | 非循環の依存 DAG のトポロジカル順。O(R+依存辺数)＋数量配分 → 再利用循環や代替レシピを線形/整数モデル化 |
| 物流経路計画 | 需要・資材・容量・輸送時間 → 発送量と経路 | 移送中、車両相当、区間残容量 / 経路・数量 | 遅延・費用・損失を最小化。発送元残、輸送時間、道路容量 | 発送 tick・道閉鎖時 | 便ごとの Dijkstra O((V+E) log V) と容量予約 → 単一品種の逐次最短路最小費用流は整数量で最大 F 回の増加。複数品種は分解・近似 |
| NPC タスク割当て | 技能・距離・優先度・締切 → 担当と開始時点 | 空き労働・キュー / 個体とタスクの割当 | 完了数・優先度を最大化し移動時間を抑える。技能・同時割当・健康を制約 | 個体 tick・完了時 | 適合スコア上位を貪欲選択 O(WT log(WT)) 上界、遠隔は集団で処理 → 小集団の二部マッチング |
| 技術開発 | 技術 DAG・資源・施設・戦略 → 研究順と投入量 | 習得済み・進捗 / 着手技術・予算 | 生産性と戦略上の価値、必須資源。前提技術・研究枠・人日・投入上限 | 週次・解禁時 | 現在選べるノードの効用を O(技術数＋前提辺数) 評価 → 短い複数期予測 |
| 国家の意思決定 | 都市収支・貿易・関係・脅威 → 交易、投資、同盟・戦争の計画 | 資金・軍事・信頼・外交履歴 / 政策と配備 | 生存、成長、多様なプレイ。予算、人員、外交クールダウンと維持費 | 日次・例外イベント時 | 優先ルールと効用採点 O(行動数×評価特徴数)、同点は固定順 → プラン候補の短期ロールアウト |

道路は、個々の端点をつなぐ最短経路と、需要を満たすためネットワーク全体にどの区間を建設するかの二段階。初期は候補経路集合を作り、MST で疎通し、実際の経路が重複する辺は一度だけ計上する。全体目的の例は `Σ_e(cost_e × built_e) + Σ_ij(demand_ij × travel_ij) + Σ_e maintenance_e`。混雑・安全も辺コストに加え、容量を制約として扱う。最短路の A* では許される最小単位コストと距離を下界に使い、近道などで下界が保証できなければゼロにする。

経済は各 tick に対し `stock'[r] = stock[r] + harvest[r] + outputs[r] - inputs[r] - use[r] - loss[r] + imports[r] - exports[r]`。採集量の初期上限は残存ノード容量・労働時間×生産性・倉庫空きの最小値。加工はレシピの投入と産出を一つの台帳取引で記録する。抽象戦闘も参加人数・補給・退却・損失を保存し、プレイヤーに近い物理戦闘は実測結果と照合する。
